# 0xHMZA

A personal notebook about security, systems, and people. Built with Jekyll, semantic HTML, a small Sass design system, and progressive enhancement.

## Run locally

Use Ruby 3.2+ and Bundler (Ruby 3.4 is recommended). On Windows, install **RubyInstaller with Devkit** (native gem compilation requires its development tools), or use WSL.

```sh
bundle install
bundle exec jekyll serve --livereload
```

Open http://localhost:4000. For a production build:

```sh
JEKYLL_ENV=production bundle exec jekyll build --strict_front_matter
python scripts/verify_site.py
```

In PowerShell, set `$env:JEKYLL_ENV = "production"` before the build command.

## Structure

- `_posts/`: published writing. Use `published: false` for unfinished posts.
- `_projects/`: project pages; only actual project documents belong here.
- `_layouts/default.html`: the shared document shell, navigation, metadata and scripts.
- `_includes/`: reusable cards, reading time, table of contents, and diagram figures.
- `_sass/`: tokens, base rules, layouts, article content, and syntax colors.
- `assets/js/main.js`: local archive filtering, contents, code copying, and table scrolling.
- `assets/js/project-art.js`: deterministic metallic landscapes, seeded from project titles and creation dates. See `docs/project-art.md`.
- `assets/js/diagrams.js`: lazy, serialized Mermaid rendering and an accessible native dialog.
- `docs/diagrams.md`: diagram authoring and review conventions.
- `test.html`: preserved infrastructure-reference prototype, excluded from production output. Its companion post remains unpublished.

Pages remain readable without JavaScript. The site uses a fixed graphite and silver-blue palette with sharp corners and unframed tags. Search controls appear only when their behavior is available. Project cards and titles are server-rendered; their decorative SVG backgrounds are generated locally without image downloads. There are no remote fonts, analytics, or search dependencies. Mermaid Tiny is pinned to 12.0.0 and requested only near a diagram. If the CDN fails, captions and source remain available.

The feed and sitemap are generated by Jekyll plugins. Internal template links use `relative_url`; social and canonical metadata use `absolute_url`. Existing article and project permalinks are preserved.

## Browser checks

Install Playwright as an optional local testing dependency (it is not part of the site):

```sh
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node scripts/check-browser.cjs
```

Run a local server on port 4000 first. The checks cover deterministic project art, title/date variation, Unicode seeds, reduced motion, desktop/mobile overflow, navigation, the fixed dark appearance (including old saved light preferences), search, every diagram, modal focus and zoom, code copying, disabled storage, blocked CDN, and JavaScript-disabled reading. Set `SITE_URL`, `PLAYWRIGHT_MODULE`, or `CHROMIUM_PATH` to use another server or an existing test runtime. Screenshots are written to ignored `.artifacts/`.
